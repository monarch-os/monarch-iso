# LUKS sector selection

New full-disk and protected free-space installations share `orchestrator/luks_calibration.py`, ported from Omarchy ISO `503aeb1`. Its executable Python AST matches upstream after branding; comments and docstrings are shortened to repository style. It requests 4096-byte encryption sectors when the target partition's byte size is divisible by 4096, otherwise leaves cryptsetup's defaults unchanged, including when the size probe fails. There is no retry of a failed format with different settings.

The policy is adapted from Omarchy ISO #336. Partition creation already uses an exclusive end converted to parted's inclusive `end - 1`. Logical partition sectors in the install JSON are separate from encryption sectors.

The free-space configurator invokes `monarch-luks-calibrate format` with its passphrase on stdin. Full-disk formatting uses upstream's per-encrypt wrapper from `luks_tuning.py`, restoring the command runner even on failure. The tuning module's executable AST also matches upstream after branding. The adapter activates it when loading the installation configuration, before filesystem operations and Installer creation.

Both paths persist `allow-discards` and `no-read-workqueue` in the LUKS2 header. Archinstall's temporary close/reopen cycles keep their mapper open until reboot, and repeated unlocks become no-ops. `MONARCH_LUKS_KEEP_OPEN=0` restores normal closing; `MONARCH_LUKS_TUNING=0` disables archinstall monkeypatches, as upstream does. Protected-install rollback still explicitly closes its own mapper through cryptsetup; it does not call the overridden archinstall lock method. Existing runtime rekey and recovery commands are unchanged.

The same module removes archinstall's systemd-run chroot wrapper and skips locale generation only when every requested locale already exists in the target archive. Both initramfs spellings receive the upstream dm-crypt options. Monarch's existing `with_sd_encrypt` validation still runs afterward, retaining its behavior for unresolved device identifiers.

The live-only `monarch-luks-calibrate.service` benchmarks Argon2id after mirror and root-image verification while the wizard is open. Both callers use upstream's 2000 ms / 512-bit-key policy. A completed root-owned boot-local cache replaces the search only with matching CPU count, full 1 GiB memory cost and sufficient memory headroom. Machines with less than 4 GiB usable RAM, reduced benchmark costs, missing or untrusted cache data and changed policies use ordinary cryptsetup calibration. Formatting cancels any pending benchmark first. The systemd sandbox denies disk access; no password or header is cached.

Existing volumes are not converted by upgrades, password changes or reconciliation. Changing their encryption sector size would require a separate supported reencryption procedure or reinstallation.

`test/unit/test_luks_format.py` covers selection, both entrypoints and real cryptsetup headers/password checks on disposable regular files. `test/unit/test_luks_calibration.py` covers cache integrity, policy and memory fallbacks, benchmark publication and service wiring. `test/unit/test_luks_tuning.py` covers mapper lifetime, persistent open flags, error propagation, chroot and locale behavior, and boot options. `bin/monarch-iso-test --encrypt` checks the root's LUKS sector size after first boot on new installs; use it both with and without `--free-space`. Reused base images retain their original format and are not subjected to the new-install assertion.
